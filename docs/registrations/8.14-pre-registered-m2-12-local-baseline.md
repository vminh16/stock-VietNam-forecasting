### 8.14 Pre-Registered M2.12 Local Baseline

Registered on 2026-09-16, before the run was started, at code revision
`60ff2be`.

Every Kronos number this project holds was produced on a rented L4. Work now
moves to a local machine. Sampled forecasts are not reproducible across hosts:
float32 rounding differences on the order of `1e-7` flip which token top-p
filtering keeps, and a single flipped token diverges the whole path. Section 3.7
established this and set the rule that a sampled `sha256` must never be compared
across hosts.

That rule protects against a false alarm. It does not answer the question this
subsection asks: **is a number measured here interchangeable with a number
measured there?** Until that is answered, no local arm can be read against any
stored L4 reference, and M3 cannot start.

#### Design

One arm, `small_l126`, on the **98 M2.5 screen dates**, `{0 mod 10}`. Those
dates are already spent on selection and this run selects nothing new on them,
so it consumes no unused date.

`evaluation/configs/m2_12_local_baseline.yaml` is identical to
`m2_5_zero_shot_screen.yaml` in every sampling and runtime field **and in
`arm_id`**. `arm_id` feeds the per-origin seed hash
`_origin_seed(seed, arm_id, origin_date)`, so holding it fixed means this run
draws the same per-origin RNG stream as the L4 run of M2.5. The only difference
between the two runs is the machine that executes them.

`batch_size` stays at 2 although the card reports 0.20 GB of 4 GB in use. Raising
it would change float reduction order and confound the one effect being measured.

**Stack under test**, recorded because no manifest field carries it:

| field | value |
|---|---|
| device | `cuda`, NVIDIA GeForce RTX 2050, compute capability 8.6 |
| torch | 2.5.1+cu121 |
| CUDA runtime | 12.1 |
| driver | 566.07 |
| python | 3.10.20 |
| os | Windows-10-10.0.26200-SP0 |

The L4 runs recorded `device: cuda` and nothing else, so the frozen artifacts
cannot be told apart from this one by any field they carry.

`output_dir` is `data/evaluation/m2_12`, a directory with no cache.
`arm_cache_key` hashes the registry, the selection, the sampler, the arm and the
model weights, but **not the device and not the torch build**. Pointing this run
at `data/evaluation/m2_5` would have resumed the L4 result and reported it as a
local one.

Budget: 13,431 origins at 5.53 origins per second, measured on a two-date probe,
**0.7 hours**.

#### Reading rule

1. **Primary is RankIC.** The comparison is against the L4 value for the same
   arm on the same dates, `0.024733`, from
   `reports/milestone_2_research_eval/zero_shot_screen/metric_summary.csv`.
2. **Threshold: `|delta| <= 0.005230`**, two seed standard deviations at 98
   dates, from the `0.002615` of section 3.8. Inside that band the host behaves
   like a seed and the local stack is admissible as a measurement origin.
   Outside it, the host effect is material and is recorded as such.
3. DA, MW-DA, CRPS, coverage, interval width and HitRate@Top10 are reported as
   **diagnostics with no pass or fail**. Their seed standard deviations differ by
   orders of magnitude, `0.000017` on CRPS against `0.004822` on coverage, so a
   uniform band would be arbitrary and a per-metric band would be six thresholds
   invented to be met.
4. **Either outcome forbids pooling.** A local number and an L4 number must never
   enter the same paired comparison. This test decides whether stored L4 values
   may still be quoted as context, not whether they may be mixed into a test.

#### What this cannot settle

- **Host effect cannot be separated from seed noise with one draw.** M2.5 and
  M2.11 ran the identical configuration on the identical dates on the same host,
  differing only in `arm_id`, and scored `0.024733` and `0.031551`. That gap is
  `0.006818`, or 2.6 seed standard deviations, so the L4 itself has already
  produced a spread wider than the band declared in rule 2. A local value inside
  the band is therefore evidence the host is harmless; a value outside it is
  **not** proof the host is to blame, and the registered response is to record
  the ambiguity, not to resolve it by assertion.
- **Whether `0.002615` is the right seed standard deviation.** It is rescaled
  from five replicates measured on the 196 dates of `{2, 5 mod 10}`, not
  measured on these 98. Resolving that needs replicates here, which this run does
  not budget.
- **Any other arm.** `base_l126`, `small_l63` and `small_l63_norm126` are not
  re-measured. A null result on the shared stack transfers by construction; a
  material one would require all of them.

No threshold in this subsection may be changed after the run is read.
